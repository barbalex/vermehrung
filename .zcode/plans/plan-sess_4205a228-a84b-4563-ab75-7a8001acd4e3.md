# Migrate vermehrung from MST/MobX to jotai (big-bang, following the ps pattern)

## Context

- MST holds **UI state only**: tree navigation, 13 filter models, errors, notifications, ~54 online/query flags, watermarks, and the offline mutation queue. Domain data lives in WatermelonDB (RxJS) — untouched by this migration. urql, graphql-ws subscriptions, Firebase auth, backend, SQL triggers: all untouched.
- No advanced MST features in use (no references, patches, middleware, env).
- Bonus: `observer` (mobx-react-lite) is incompatible with the **React Compiler that is already enabled** (`vite.config.ts:77`, see mobxjs/mobx#3874). jotai is compiler-compatible.
- **Reference implementation**: `ps` project (`/home/alex/Documents/GitHub/ps`) — same queue-drain pattern in jotai: `observe()` from `jotai-effect` + vanilla `store` + retry-tick atom + `isProcessing` guard (`ps/src/modules/observeOperations.ts`, `ps/src/components/OperationsObserver.tsx`, `ps/src/store.ts`). We port this structure.
- **Accepted**: users lose persisted local state **once** (queued offline operations, tree/filter state, watermarks). No migration from the old localforage `store` key — we use fresh keys. Watermark reset just causes a full subscription re-pull on first boot; WatermelonDB data itself is not lost.

## Decisions (confirmed with user)

- **Big-bang rewrite** in one pass (not strangler).
- **Add vitest** with tests covering the new queue-drain engine's behavior contract, derived line-by-line from the current MST reaction (`src/store/index.js:133-255`).

## New / removed dependencies

- Add: `jotai` (2.20.2), `jotai-effect` (2.4.1) — same versions as ps. Dev: `vitest`, `test` script.
- Remove at the end: `mobx`, `mobx-react-lite`, `mobx-state-tree`, `mst-persist`, and the dead `observable-hooks` (never imported).

## Step 1 — Test setup

- `npm i -D vitest`, add `"test": "vitest run"` script. No config file needed initially (vite project, vitest picks up `vite.config.ts`).

## Step 2 — New jotai store: `src/store/` rewritten (old MST store deleted at the end)

`src/store/index.js` exports `store = createStore()` plus atoms, mirroring ps conventions:

- **Plain flags** (~55): `onlineAtom`, `shortTermOnlineAtom`, `isPrintAtom`, `singleColumnViewAtom`, `showTreeInSingleColumnView`, `diffConflictAtom`, `initiallyQueryingAtom`, `wsReconnectCountAtom`, `gettingAuthUserAtom`, `authorizingAtom`, `docFilter`, `docsCount`, `apFilter`…
- **Tree state** (persisted): `activeNodeArrayAtom`, `lastActiveNodeArrayAtom`, `openNodesAtom`, `widthInPercentOfScreenAtom`. The `getParent` couplings in `Tree.js:29/67` become plain functions: `setActiveNodeArray(path)` also calls `store.get(navigateAtom)?.(path)`; `singleRowHeight` reads the flags it needs directly.
- **Filters** (persisted): one atom per table (13), plain nullable-field objects; `setValue` write-atoms; the `filtered`/`koenig` views become derived atoms (`src/store/Filter/` rewritten, much smaller — drop the `types.union` boilerplate).
- **Errors**: `errorsAtom` (single plain object `table.field → message`) + `setErrorAtom`/`unsetErrorAtom` write atoms (replaces 12 sub-models; the dynamic `set(self.errors, path, value)` at `index.js:309` becomes a simple object spread).
- **Notifications**: `notificationsAtom` (array) + `addNotificationAtom`/`removeNotificationAtom` (replaces types.map + identifier).
- **Queue** (persisted, localforage-backed `atomWithStorage` with a `localforage` async storage adapter): `queuedQueriesAtom` (array of plain queued-query objects, same fields as `QueuedQuery.js`), derived `queuedQueriesSortedAtom` (by time), `retryTickAtom`.
- **Watermarks** (persisted): 27 `xxxLastUpdatedAtom` + 27 `xxxInitiallyQueriedAtom` (can be two atoms holding objects keyed by table — decide during implementation, keep component access ergonomic).
- **Volatile singletons**: `userAtom`, `firebaseAuthAtom`, `gqlClientAtom`, `gqlWsClientAtom`, `dbAtom`, `navigateAtom` (plain `atom(null)` — replaces MST volatiles).
- **Derived**: `initialDataQueriedAtom`, `activeFormAtom`, and the `xxxIdInActiveNodeArray` getters as derived atoms.
- Deduplicate the 14 near-identical `insert*Rev` actions (`index.js:398-1401`, ~1,000 lines) into **one generic module** `src/modules/insertRev.js` parametrized by table name, driven by the existing per-table mutation catalog in `src/utils/mutations.js`.
- Keep a debug hook: `window.store = store` (dev).

## Step 3 — Queue-drain engine (port of `index.js:133-255` to the ps structure)

- `src/components/QueuedQueriesObserver.jsx` — mounted once in App; starts the observer, `setInterval` 30 s (current behavior) incrementing `retryTickAtom`; unobserves on beforeunload.
- `src/modules/observeQueuedQueries.js` — `observe(async (get) => {...}, store)` with `isProcessing` guard (ps pattern); port every branch of the current reaction:
  - JWT error → `getAuthToken()`
  - `_rev_id__rev_key` uniqueness violation → ignore + remove (identical duplicate edit)
  - status 21000 ("same edit too soon") → defer to end of queue
  - unique-constraint violation → set field error via `setErrorAtom`
  - `Failed to fetch` → `store.set(shortTermOnlineAtom, false)` (stays queued, retried on tick)
  - other errors → move to end of queue + error notification with "delete operation" action
  - success → remove from queue
- `src/modules/executeQueuedQuery.js` (one query → `store.get(gqlClientAtom).mutation(...).toPromise()`), `revertQueuedQuery.js`, `removeQueuedQuery.js` — mirroring ps module layout.

## Step 4 — Vitest tests for the drain engine

`src/modules/__tests__/observeQueuedQueries.test.js`: mock gqlClient (urql `mutation().toPromise()`), fake timers for the tick, `store` from the real store module. Cover: oldest-first order, success removal, `isProcessing` re-entrancy guard, each error branch above, offline gate. The expectations are written from the current MST behavior (characterization), then verified against the new engine.

## Step 5 — Convert consumers (~250 files)

- **227 components**: remove `observer` import/wrap; replace `useContext(MobxStoreContext)` + destructuring with `useAtomValue`/`useSetAtom`. Replace `getSnapshot(...)` in the 5 Tree files (state is plain data now); `.toJSON()` in Root/Herkuenfte becomes direct atom values.
- **`src/dbModel.ts` (12 model classes)**: `edit({ field, value, store })` drops the `store` param; import `store` + atoms directly (`store.set(addQueuedQueryAtom, ...)`, `store.get(userAtom)`, `store.get(dbAtom)`). Same for all callers.
- **~21 utils** receiving `store` (`initializeSubscriptions`, `processSubscriptionResult`, `checkForOnlineError`, `deleteAccount`, …): same — direct atom imports.
- **`src/App.jsx`**: drop `MobxStoreProvider`; urql `Provider` gets `store.get(gqlClientAtom)`; mount `QueuedQueriesObserver`.
- **`src/utils/recreatePersistedStore.js` → slim bootstrap**: Firebase `onAuthStateChanged` → `setUserAtom`, `isOnline()`, `getAuthToken()`; persistence now happens via `atomWithStorage` (hydration automatic); old localforage `store` key left orphaned (ignored).

## Step 6 — Cleanup & verification

- Delete `src/store/index.js` MST models, `Filter/` MST files, `Errors/`, `Tree.js`, `Notification.js`, `QueuedQuery.js`, `src/mobxStoreContext.js`; uninstall the 5 mobx-family packages.
- `npm test` (new vitest suite), `npm run build`, then dev-server browser smoke test: app boots, tree navigation, filter, form edit enqueues + drains (can simulate offline via devtools), QueuedQueries UI, notifications.

## Out of scope (unchanged)
